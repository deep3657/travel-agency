## 1. Purpose and Scope

This Low-Level Design (LLD) document fills the implementation gap between `HLD.md` and code. It specifies, for each module identified in HLD §6:
- Database tables (column names, types, constraints, indexes).
- Eloquent models and their relationships, casts, and scopes.
- HTTP routes and method signatures.
- Form-request validation rules.
- Authorization policies and the full RBAC matrix.
- Service- and action-class signatures and their responsibilities.
- Livewire component public surface (properties, methods, emitted events).
- Queued jobs, notifications, and scheduled commands.
- Configuration files and environment variables.
- AI extraction client design.
- Test approach and key test scenarios.

This LLD does not repeat what is already in PRD or HLD. Functional behaviour comes from the PRD; architectural rationale and cross-cutting decisions come from the HLD; this document is the engineer's working reference for "what file/class/table do I create and what's in it".

## 2. Conventions

### 2.1 Naming
- Tables: snake_case plural (`bookings`, `quotation_versions`).
- Models: PascalCase singular (`Booking`, `QuotationVersion`).
- Pivot tables: alphabetical singular_singular (`booking_passenger`).
- Foreign keys: `{singular_referenced_table}_id` (`booking_id`, `quotation_version_id`).
- Enums: stored as VARCHAR with a PHP `BackedEnum` cast and a CHECK constraint where MySQL supports it.
- Services: `{Module}Service` (`BookingService`); actions: `{Verb}{Module}Action` (`CreateQuotationAction`).
- Form requests: `{Verb}{Resource}Request` (`StoreBookingRequest`).
- Policies: `{Resource}Policy` (`BookingPolicy`).
- Livewire components: `App\Livewire\{Module}\{Name}` (e.g., `App\Livewire\Booking\BookingForm`).
- Jobs: `App\Jobs\{Module}\{Verb}{Action}Job` (`App\Jobs\Voucher\GenerateVoucherJob`).
- Notifications: `App\Notifications\{Verb}{Subject}Notification`.

### 2.2 Money, dates, identifiers
- Money: `DECIMAL(12,2)` in INR; cast as a `Money` value object via `App\Casts\MoneyCast`.
- Percentages (GST rates): `DECIMAL(5,2)`.
- Timestamps: stored UTC; cast via Laravel `datetime`. App timezone `Asia/Kolkata`.
- Public-facing IDs: ULIDs in URLs (`Str::ulid()`); auto-increment `bigint` in DB. Both stored on row.
- Booking reference: human-friendly `BK-{YYYY}-{seq6}` generated by `BookingRefGenerator`.

### 2.3 Soft deletes
- Soft-deletes used on: `customers`, `vendors`, `packages`, `email_templates`, `users`. Not used on transactional records (`bookings`, `quotations`, `change_requests`) — these use status fields instead.

### 2.4 Versioning of generated documents
- Every generated PDF (quotation, voucher, invoice) writes a new row in `documents` with a monotonically increasing `version_number` per parent (quotation_version_id or booking_id + doc_type). Old rows are kept; the latest is the "current" one.

## 3. Database Schema

### 4.1 User
```
class User extends Authenticatable {
    use HasRoles, HasFactory, SoftDeletes, Notifiable;

    protected $fillable = ['name','email','phone','password','user_type','customer_id','is_active'];
    protected $hidden = ['password','remember_token'];
    protected $casts = ['email_verified_at'=>'datetime','is_active'=>'boolean'];

    public function customer(): BelongsTo { return $this->belongsTo(Customer::class); }
    public function assignedEnquiries(): HasMany { return $this->hasMany(Enquiry::class,'assigned_user_id'); }
    public function assignedTrips(): HasMany { return $this->hasMany(Trip::class,'assigned_user_id'); }

    public function isAdmin(): bool { return $this->hasRole('admin'); }
    public function isAgent(): bool { return $this->hasRole('agent'); }
    public function isCustomer(): bool { return $this->user_type === 'customer'; }
}
```

### 4.2 Customer
```
class Customer extends Model {
    use HasFactory, SoftDeletes, LogsActivity, TracksAuthor;

    protected $fillable = [/* all customer columns */];
    protected $casts = ['dob'=>'date','anniversary'=>'date','tags'=>'array'];

    public function enquiries(): HasMany { return $this->hasMany(Enquiry::class); }
    public function trips(): HasMany { return $this->hasMany(Trip::class); }
    public function bookings(): HasMany { return $this->hasMany(Booking::class); }
    public function user(): HasOne { return $this->hasOne(User::class); }

    public function getActivitylogOptions(): LogOptions {
        return LogOptions::defaults()->logOnly(['name','phone','email','gstin','address_line1','city','state','pincode'])
            ->logOnlyDirty()->dontSubmitEmptyLogs();
    }
}
```

### 4.3 Booking
```
class Booking extends Model {
    use HasFactory, LogsActivity, TracksAuthor, HasUlid;

    protected $casts = [
        'flight_data'=>'array','hotel_data'=>'array','package_data'=>'array',
        'sale_amount'=>MoneyCast::class,'purchase_cost'=>MoneyCast::class,'margin'=>MoneyCast::class,
        'customer_payment_due'=>'date','vendor_payment_due'=>'date',
    ];

    public function trip(): BelongsTo { return $this->belongsTo(Trip::class); }
    public function customer(): BelongsTo { return $this->belongsTo(Customer::class); }
    public function vendor(): BelongsTo { return $this->belongsTo(Vendor::class); }
    public function passengers(): BelongsToMany {
        return $this->belongsToMany(Passenger::class)->withPivot('is_lead')->withTimestamps();
    }
    public function documents(): HasMany { return $this->hasMany(Document::class); }
    public function supplierDocuments(): HasMany { return $this->hasMany(SupplierDocument::class); }
    public function changeRequests(): HasMany { return $this->hasMany(ChangeRequest::class); }
    public function reminders(): HasMany { return $this->hasMany(Reminder::class); }

    public function getActivitylogOptions(): LogOptions {
        return LogOptions::defaults()->logOnly([
            'sale_amount','purchase_cost','vendor_id','agency_pnr','vendor_pnr',
            'status','payment_status','customer_payment_due','vendor_payment_due',
            'flight_data','hotel_data','package_data',
        ])->logOnlyDirty()->dontSubmitEmptyLogs();
    }

    protected static function booted(): void {
        static::creating(function (Booking $b) {
            $b->booking_ref ??= app(BookingRefGenerator::class)->next();
            $b->ulid ??= (string) Str::ulid();
        });
    }
}
```

## 5. Routes

Routes live in three files registered by `RouteServiceProvider`:
- `routes/web.php` — admin/agent portal under `/admin` prefix, `auth`, `verified`, `staff` middleware.
- `routes/customer.php` — customer site, mostly public + `/account` under `auth:customer` middleware.
- `routes/api.php` — minimal; only used for Livewire-internal AJAX (Livewire owns its own endpoints).

### 7.3 Three-layer financial-field hiding (HLD §9.2)

1. **Form requests** — `passedValidation()` strips `purchase_cost`, `margin`, `vendor_id`, `vendor_payment_due` for Agents (§6.4 / §6.5).
2. **Eloquent global scopes** — `BookingObserver::retrieved()` and `QuotationLine::retrieved()` overwrite financial attributes with null when `auth()->user()?->isAgent()`.
3. **Blade templates** — `@can('viewFinancials', $booking) ... @endcan` wraps the columns/sections.

### 8.7 BookingRefGenerator
- Atomic counter backed by a dedicated `bookings_seq (year INT PRIMARY KEY, last_seq INT NOT NULL DEFAULT 0)` table. The `next()` method opens a transaction, runs `UPDATE bookings_seq SET last_seq = last_seq + 1 WHERE year = ?`, falls back to `INSERT IGNORE INTO bookings_seq (year, last_seq) VALUES (?, 1)` on first call of the year, then `SELECT last_seq` to read the new value. The row-level lock guarantees uniqueness across web and queue without `LOCK TABLES`. The format is `BK-{YYYY}-{seq6}` zero-padded to 6 digits.

### 13.4 Cost computation
- Gemini 2.0 Flash: input ~$0.075/1M tokens, output ~$0.30/1M tokens. Convert to INR using a configurable `gemini_inr_per_usd` (default 84). Each PDF page ≈ 250 input tokens (image-equivalent) + completion ≈ 500 tokens → ~₹0.05.
- OpenAI GPT-4o-mini: input ~$0.15/1M, output ~$0.60/1M → ~₹0.15 per typical doc.
- Stored on every `extraction_jobs` row in `estimated_cost_inr`.

```
  supplier_docs/{booking_id_or_staging_uuid}/{uuid}.{ext}
  package_images/{package_id}/{uuid}.{ext}
  enquiry_attachments/{enquiry_id}/{uuid}.{ext}
  branding/logo.{ext}
```

Signed download flow:
1. Service computes a one-time `URL::temporarySignedRoute('files.download', now()->addMinutes(15), ['file_id' => $doc->id])`.
2. `SignedFileController::download()` validates the signature, runs the matching policy (`viewBookingDocument`, `viewSupplierDoc`, etc.), streams the file via `Response::download()`.

## 20. Appendix

### 20.1 Glossary additions to PRD §A
- **DTO**: Data Transfer Object — typed PHP class used to carry validated form data into a service. Lives under `app/Modules/{Module}/DTOs/`.
- **Action**: A queueable single-purpose class implementing `ShouldQueue`. Differs from a Service which is synchronous and exposes multiple methods.
- **View Model**: Typed PHP class used to populate Blade views (especially PDFs) so the template has zero database/business logic.
- **Three-layer hiding**: The defence-in-depth pattern for stripping financial fields from Agent users (Form Request + Eloquent retrieved hook + Blade gate).
