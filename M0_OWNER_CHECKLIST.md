## Required actions (in suggested order)

### 1. Domain registration

- [ ] Register the production domain (e.g. `marutitravels.in`, `marutitravels.com`, or your preferred TLD).
- [ ] Note the domain registrar credentials in your password manager.
- [ ] Decide the customer-facing URL (e.g. `marutitravels.in`) and admin/internal URL (e.g. `admin.marutitravels.in`). Single-domain works for v1; subdomain split is fine too.

**Why first**: Cloudflare and Cloudways both need this. Register early because TLD propagation and registrar verification can take 24–48 h.

---

### 2. GitHub organisation + repository

- [ ] Create a GitHub organisation (e.g. `maruti-travels`) or use a personal account.
- [ ] Create a private repository: `maruti-travels/portal` (or your preferred name).
- [ ] Add me as a collaborator if you want me to push directly; otherwise we'll use PRs from forks.
- [ ] Once you tell me the repo URL, I'll initialise it from the local scaffold and push the M0 branch.

**Why second**: Cloudways native Git deploy pulls from this repo, so it must exist before deploy hooks are configured.

---

### 3. Cloudways account + Laravel server

- [ ] Sign up at [https://cloudways.com](https://cloudways.com).
- [ ] Add a payment method (UPI / card).
- [ ] Provision a server:
  - **Application**: Laravel 11
  - **Cloud provider**: AWS or DigitalOcean (DO is cheaper)
  - **Server size**: 2 vCPU / 4 GB (Implementation Plan §16, HLD §9.5)
  - **Region**: Mumbai (`ap-south-1` or DO Bangalore equivalent)
  - **Server name**: `maruti-portal-prod`
  - **Application name**: `portal`
- [ ] Once provisioned, share with me:
  - SSH credentials or "Master Credentials" tab values
  - Application public IP / temporary `cloudwaysapps.com` URL
  - Database credentials (auto-generated by Cloudways)
- [ ] Enable **Cloudways daily snapshot service** (HLD §9.10 — required since v1 has no off-server backup).
- [ ] Configure **native Git deploy**: Application → Deployment Via Git → connect the GitHub repo from step 2.

**Cost**: ~₹2,000–3,000 / month for the VPS + DB tier.

---

### 4. Cloudflare account + DNS

- [ ] Sign up at [https://cloudflare.com](https://cloudflare.com) (free tier is fine for v1).
- [ ] Add the domain from step 1 to Cloudflare.
- [ ] Update nameservers at the registrar to Cloudflare's nameservers.
- [ ] Once nameservers propagate, point the production hostname to the Cloudways IP via an `A` record (proxied / orange cloud ON for WAF + TLS).
- [ ] Enable **Full (Strict)** TLS mode (Cloudways provides Let's Encrypt origin cert; toggle in the Cloudways application panel).
- [ ] Enable WAF (free tier rules are sufficient for v1).
- [ ] Configure the rate-limit rule from HLD §16.2:
  - Path: `/healthz`, `/login`, `/signup`, `/forgot-password`, `/quotation/*/pdf`
  - Limit: 60 requests / minute / IP

---

### 5. Brevo (formerly Sendinblue) — transactional email

- [ ] Sign up at [https://brevo.com](https://brevo.com).
- [ ] Verify the sending domain (DKIM, SPF, DMARC records — Brevo provides them, you add them in Cloudflare DNS).
- [ ] Create an SMTP key under Settings → SMTP & API.
- [ ] Share with me:
  - `MAIL_USERNAME` (login email shown in SMTP settings)
  - `MAIL_PASSWORD` (the SMTP key)
  - `MAIL_FROM_ADDRESS` (e.g. `bookings@marutitravels.in`)

**Free tier**: 300 emails/day. Sufficient for v1 launch traffic.

---

### 6. Google Cloud / Gemini API

- [ ] Sign in to [https://aistudio.google.com](https://aistudio.google.com) with the Google account that will own AI billing.
- [ ] Create a new API key (free tier exists; paid tier for production).
- [ ] Set a monthly billing cap of **₹500** in Google Cloud Console → Billing → Budgets, with email alerts at 50%/80%/100%.
- [ ] Share `GEMINI_API_KEY` with me.

**Note**: AI extraction is an *optional* feature (admin can always fall back to manual entry). It can be wired up at any time before M11; not blocking M1–M10.

### 8. UptimeRobot (or similar)

  - URL: `https://<production-domain>/healthz`
  - Interval: 5 minutes
  - Alert contact: your phone (SMS) and / or email
- [ ] Optional: WhatsApp alerts via integration.

**Why last**: Needs the production URL from steps 3–4 first.
