1. About this portal

The Maruti Travels Portal is a single Laravel application that replaces the spreadsheet + WhatsApp + email workflow that travel agencies typically run on. It is split into two surfaces:

  • Admin portal — used by the agency's owner, managers and operations agents to run the full enquiry → quotation → booking → voucher → cancellation lifecycle.
  • Customer-facing site — a lightweight public website with package browsing, sign-up, and a private "My account" area where customers can raise enquiries and download their own vouchers.

What problem does it solve? One source of truth for customer history, GSTIN, bookings and payments; standardised branded PDFs; per-booking cost/profit capture visible only to admins; a reminder engine for travel events and payment dues; and a customer self-service surface that replaces ad-hoc PDF email threads.

3. Feature reference

3.1 Customer master

The address book of the agency. Customers enter the system in three ways:

  • Self-signup via the public website (/customer/register).
  • Admin manual creation from /admin/customers/create.
  • Auto-creation when an enquiry is submitted (matched by email + phone).

Searchable by name, phone, email, GSTIN. The detail page has tabs for Profile, Enquiries, Trips, Bookings, Documents, Upcoming travels, Payments.

Validation: phone & email are unique; GSTIN is regex-validated (15 chars, standard pattern); PAN is optional but regex-validated when present.

3.2 Vendor master Admin only

Suppliers used as the FK on bookings — airlines, hotel chains, B2B portals (Tripjack, TBO, MakeMyTrip B2B, IRCTC). Agents see vendor names only on bookings they have access to; they cannot list, edit, or delete vendors. Useful aggregations like "top 10 vendors by purchase value" feed the admin dashboard.

3.3 Standard packages

Admin-curated tour packages with rich content for the public site:

  • Title, slug, destinations, duration (days/nights), price-from, departure city.
  • Hero image + gallery (up to 10 images).
  • Short + long description, highlights, inclusions, exclusions, T&Cs.
  • Day-wise itinerary (day number, title, description, optional image).
  • Category tags (Honeymoon / Family / Adventure / Pilgrimage / International / Beach / Hill).
  • Workflow status: Draft / Published / Archived. Only Published packages appear on the public site.

Public list view has filters by category, destination, duration band and price band. The detail page has a "Send enquiry" CTA that pre-fills the enquiry form with the package reference.

3.4 Enquiries

The agency's pipeline of demand. Stored fields include enquiry type (Flight / Hotel / Package / Mixed), travel dates, origin, destination, pax counts (adults/children/infants), budget range, special requirements, source (Website / Walk-in / Phone / Referral / WhatsApp / Other), status, assigned agent and a notes timeline.

Lifecycle

New → In Progress → Quoted → Converted (linked to a Trip) / Lost / Cancelled

Admin inbox

  • Filters: status, agent, date range, type.
  • Bulk-assign, status pipeline view.
  • One-click "Send template reply" using saved Reply Templates (rich text + placeholders), logged in the notes timeline.
  • Convert to Trip action in the sidebar of any enquiry detail page — creates a Trip with the customer, destination, dates and notes carried over, and bumps the enquiry to In Progress.

Customer side

The enquiry form is available from every package detail page and from "My account → Enquiries". When the customer is logged in, name and phone are taken from their profile — they aren't asked again.

3.5 Trips

A Trip is a container that groups all the artefacts of one customer journey: every quotation version, every booking (flight/hotel/package), every cancellation, every voucher, every reminder.

Two ways to create a Trip:

  1. Convert from enquiry — the recommended path. Carries over customer, destination, dates, notes and the assigned agent.
  2. Direct creation at /admin/trips/create. Useful when the customer already exists and the conversation started outside the portal.

The trip detail page aggregates all sub-artefacts and shows a running payment-status summary.

3.6 Quotations & quotation editor

Quotations are versioned — once a version is sent it becomes immutable; edits create a new version (v1, v2, v3…). Every version is downloadable from history.

  • Multi-line items, one per service (flight / hotel / package / other).
  • Type-specific structured fields per line (sectors, hotel name, room type, package ref, etc.).
  • Admin-only fields per line: vendor, purchase cost, margin (auto-calculated as sale − cost). Hidden from agents and absent from the PDF.
  • GST auto-calc: same state as agency → CGST + SGST; different state → IGST. Rates configured per service type in Agency settings.
  • Totals: subtotal, discount (₹ or %), GST, grand total.
  • Actions: Save draft, Generate PDF, Email to customer, Mark accepted (transitions the trip to Confirmed).
  • Admin History tab on the quotation detail page shows field-level diffs for every change (user, timestamp, field, old → new).

3.7 Bookings & passengers

One Booking per service unit. A trip with flight + hotel + package = three bookings.

Common fields: trip ref, customer, booking type, system reference (auto-generated, e.g. BK-2026-00001), agency PNR, supplier/vendor + vendor PNR/voucher number, sale amount, purchase cost Admin only, margin Admin only, payment status (Unpaid / Partial / Paid), customer & vendor payment due dates, status (Pending Confirmation / Confirmed / Cancelled / Completed).

Passengers are linked many-to-many. Per-pax fields include title, name, DOB, nationality, passport (international), meal preference and a lead-passenger flag. A "copy passengers from another booking in this trip" helper avoids re-keying.

Voucher generation: one click renders the right voucher PDF and stores it against the booking. Regeneration is "drop and create" — a new version is written; previous versions remain visible in the Documents tab.

3.8 Supplier documents & AI extraction

When the agency books offline on a supplier portal (Tripjack, TBO, IRCTC…), the supplier issues its own PDF. This module lets admins (a) attach the supplier file to a booking for audit, and (b) re-issue the booking as a Maruti Travels branded voucher.

Two entry points

  1. Standalone — /admin/supplier-docs/new. Upload → pick customer + trip → choose extraction mode → review form → save. Use when the booking doesn't exist yet in the portal.
  2. From a booking — "Upload supplier document" action on the booking detail page. Use when the booking already exists.

Two extraction modes

ModeHow it worksCost
ManualAdmin keys booking fields by hand. The supplier PDF is stored for audit with SHA-256 hash and uploader info.Free; always available.
AI-assistedA queued job sends the file to the configured vision model (Gemini 2.0 Flash → fallback to GPT-4o-mini). The model returns structured JSON with per-field confidence scores; fields below the configurable threshold (default 0.7) are highlighted in red. Admin must Save; nothing auto-persists.~₹0.03–0.10 per document.

Budget cap: a monthly cap (default ₹300) auto-disables AI mode for Agents on breach (redirects them to Manual). Admins see a warning with an explicit Override and use AI anyway button — every override is audit-logged. The cap resets at the start of each calendar month (server timezone).

3.9 Cancellation & change requests

Linked one-to-many to bookings. Fields include request type (Cancellation / Flight Change / Hotel Change), reason, status, assigned agent, notes timeline and a refund accounting block:

  • Vendor cancellation/change fee
  • Refund amount from vendor to agency
  • Agency service fee
  • Net refund to customer (auto-derived)
  • Refund mode (Cash / Bank transfer / Adjustment) and refund-settled date.

On completion: the parent booking status flips to Cancelled (or the voucher is regenerated for Change), and a template-based summary email goes to the customer.

3.10 Audit log Admin only

Field-level activity log is enabled on Bookings, Passengers, Quotations, Quotation Versions, Quotation Lines, Cancellation/Change Requests, and Supplier Document uploads. Every create / update / delete is captured with acting user, timestamp and a field-level diff (old → new). The History tab is visible to Admin only and there is no UI to delete or edit log entries.

4. Customer-facing portal

The public site lives under / (home), /packages, /about and /contact. The customer-authenticated area lives under /account/* behind a separate customer auth guard.

4.1 Public pages

  • Home — hero + featured packages.
  • Packages list — filters by category, destination, duration, price.
  • Package detail — gallery, full itinerary, inclusions/exclusions, "Send enquiry" CTA.
  • About / Contact — static + functional contact form (creates a Customer + Enquiry when submitted; rate-limited).

4.2 Authenticated customer area

  • Dashboard — upcoming trips, recent enquiries.
  • Profile — edit name, phone, address, GSTIN.
  • My enquiries — list, detail, add note, raise a new enquiry (form pre-fills name & phone from the session).
  • My trips — list and detail with bookings, voucher download buttons, and "Request cancellation/change" per booking.

Cross-tenant safety: every customer-area policy method ensures the requester's customer_id matches the resource's. URL tampering (e.g. /account/trips/<other-ulid>) returns HTTP 404. Internal financial fields (purchase cost, vendor name, margin) are stripped from every customer-facing response, even for resources the customer is allowed to read.

5. Documents & PDF generation

Five system templates ship with v1:

  1. Quotation
  2. Flight Ticket Voucher
  3. Hotel Voucher
  4. Package Voucher
  5. GST Invoice / Receipt

5.1 What's configurable

  • Header: logo, agency name, address, GSTIN, phone, email, website.
  • Footer: terms text, signature image.
  • Accent colour (hex).
  • Field-visibility toggles (e.g. hide vendor name on voucher).
  • Email subject & body template per document type, with placeholders ({{customer_name}}, {{booking_ref}}, {{travel_date}}, …).

Free-form WYSIWYG layout editing is intentionally out of v1 — layouts are fixed Blade templates so the rendered PDFs stay consistent and pixel-stable.

5.2 Drop-and-create versioning

Regenerating a voucher creates a new stored PDF; the previous version is retained and listed under the booking's Documents tab. This is intentional for audit and historical accuracy when bookings change after issue.

5.3 Rendering pipeline

The portal uses laravel-snappy (wkhtmltopdf) as the primary renderer because it produces print-stable layouts. laravel-dompdf is wired as an automatic fallback for environments where the wkhtmltopdf binary is unavailable. Both points are configured in .env:

SNAPPY_PDF_BINARY=/opt/homebrew/bin/wkhtmltopdf
SNAPPY_IMAGE_BINARY=/opt/homebrew/bin/wkhtmltoimage

A daily scheduled job reads upcoming bookings and produces queued notifications. A small bell icon in the admin header shows unread count and the latest 50 reminders.

8.4 Configuring AI extraction

The AI vision feature is off by default. To enable it:

  1. Obtain a Gemini API key (Google AI Studio) — or an OpenAI key, or both.
  2. Set AI_ENABLED=true in .env.
  3. Populate GEMINI_API_KEY (recommended primary) and optionally OPENAI_API_KEY as fallback.
  4. Set the monthly cap to a value you're comfortable with — typical agencies sit at ₹200–300/month.
  5. Restart the queue worker so it picks up the new env: php artisan queue:restart.

8.5 Configuring SMTP (Brevo / Sendinblue)

  1. Sign up for Brevo (free tier = 300 emails/day; ~₹600/month for 20k transactional).
  2. Create an SMTP key and put the credentials in .env:
MAIL_MAILER=smtp
MAIL_HOST=smtp-relay.brevo.com
MAIL_PORT=587
MAIL_ENCRYPTION=tls
MAIL_USERNAME=your-brevo-login
MAIL_PASSWORD=your-smtp-key
MAIL_FROM_ADDRESS=bookings@yourdomain.com
MAIL_FROM_NAME="${APP_NAME}"

Send a test email from Settings → Email diagnostics (or with php artisan tinker → Mail::raw(...)).

8.6 Configuring branding

Navigate to Settings → Agency profile and upload:

  • Agency logo (PNG/SVG, transparent background preferred).
  • Letterhead signature image (PNG with transparent background).
  • Accent colour (hex) — used on PDF headers and the email button.
  • Default terms & conditions text — appears on all quotations and invoices.

Then visit Settings → GST & tax and set:

  • Agency GSTIN (15-char regex validated).
  • Agency state (drives CGST+SGST vs IGST split).
  • GST rate per service type (default: 5% packages, 18% commission-based — confirm with your CA).

9. Production checklist

Use this list before pointing your DNS at a staging deploy and again before declaring "go-live":

9.1 Application

  • APP_ENV=production and APP_DEBUG=false
  • APP_KEY set and backed up in your secret manager (re-generating it invalidates all encrypted cookies and tokens).
  • APP_URL matches the actual HTTPS hostname.
  • SESSION_SECURE_COOKIE=true.
  • php artisan config:cache & php artisan route:cache & php artisan view:cache after deploy.
  • php artisan storage:link if you've enabled public storage (not used by default).

9.2 Hosting & processes

  • Web server: Nginx → PHP-FPM 8.2 (Cloudways / Forge handle this automatically).
  • wkhtmltopdf installed and the path matches SNAPPY_PDF_BINARY.
  • Cron entry: * * * * * cd /var/www/portal && php artisan schedule:run >> /dev/null 2>&1
  • Supervisor service for the queue worker: php artisan queue:work --tries=3 --backoff=30 --sleep=2
  • HTTPS with auto-renewal (Let's Encrypt). Add HSTS in the reverse-proxy config.

9.3 Security

  • Rotate the seeded demo admin password (or delete the demo accounts).
  • Database user has access only to the application database (no SUPER, no other schemas).
  • .env permissions: chmod 600 and owned by the deploy user.
  • Verify the storage/app/private directory is outside the web root.
  • Smoke-test: try downloading another customer's voucher by manipulating the URL — should return 404.

9.4 Backups

  • Provider snapshots enabled (Cloudways & DigitalOcean both offer hourly/daily snapshot windows).
  • Off-server backup of storage/app/private (S3-compatible). Retention: 14 nightly + 12 monthly.
  • Manual restore drill documented and run at least once before go-live.

9.5 First-day checks after going live

  1. Open the public site at the production URL — packages render and images load.
  2. Sign up as a customer with a real email — verification email arrives within a minute.
  3. Log into the admin portal and create a Trip end-to-end: enquiry → convert → quotation → PDF → email → booking → voucher.
  4. Confirm the queue worker is running: php artisan queue:work --once on the server should pick up jobs.
  5. Confirm the scheduler fired today: php artisan schedule:list shows registered tasks.

10.3 Known operational gotchas

Do not import Alpine.js separately. Livewire 3 bundles its own Alpine. Adding import Alpine from 'alpinejs'; Alpine.start() in resources/js/app.js causes a "Detected multiple instances of Alpine running" error and silently breaks wire:click handlers across the entire admin UI.

PHP 8.5 deprecation noise. Until you upgrade Laravel 11 → 12, PDO::MYSQL_ATTR_SSL_CA emits deprecation warnings under PHP 8.5. These are suppressed in public/index.php for development; do not re-enable verbose deprecation reporting in production until the framework upgrade lands.

11. Frequently asked questions

11.1 Roles, accounts & access

A new staff member joined — how do I add them?

Sign in as Admin → Settings → Users → Invite user. Enter their email and pick a role (Admin or Agent). They receive a verification email with a link to set their own password. You can revoke access from the same screen.

An agent is asking why they can't see vendor names on bookings — is this a bug?

No, it is by design. Agents only see sale prices; purchase cost, vendor, and margin are hidden at the controller and view layers (defence in depth). If a specific agent legitimately needs that visibility, promote them to the Admin role.

Can a customer accidentally see another customer's trip?

No. The customer auth guard plus the TripPolicy enforce that the requesting customer's id must match the trip's customer_id. URL-tampering attempts return HTTP 404. There is automated test coverage for this.

A customer says they never got their verification email — what now?

First, check the SMTP provider's dashboard (Brevo → "Transactional"); 99% of issues are bounced emails or rate-limit throttling. If the email did go out, ask them to check Spam. As a fallback, from the admin user-detail screen click Mark email verified.

11.2 Day-to-day workflow

A walk-in customer just called — what's the fastest path from call to voucher?

1) Open Enquiries → New and capture the request (source = Phone or Walk-in).
2) From the enquiry sidebar click Convert to trip.
3) On the trip page, Add quotation, fill the line items, hit Generate PDF and Email to customer.
4) When the customer accepts, click Mark accepted and create the bookings directly from the line items.
5) Generate vouchers from each booking.

I need to create a Trip but there's no enquiry. Is that possible?

Yes. Go to Trips → New trip. Pick the customer (or create one first), then fill name, destination, dates and assign an agent. The trip name auto-suggests Customer · Destination · Month Year; override as you like.

A customer wants to change their dates — do I create a new booking?

No, raise a Change request from the booking detail page. Fill in vendor change fee, agency fee, and any refund/charge to the customer. On completion, the voucher is regenerated automatically (drop-and-create).

A booking shows the wrong total — how do I correct it without losing the original PDF?

Edit the booking; click Regenerate voucher. Drop-and-create keeps the previous PDF version visible in the Documents tab so audit history is intact.

How do I email a quotation again to the same customer?

On the quotation detail page, the Email action is always available. The most recent version (vN) is attached; previous versions remain downloadable from the version dropdown.

Can two agents work on the same enquiry at once?

Yes — there is no hard lock. Livewire reactive updates mean each agent sees the other's saves within seconds. Use the notes timeline to coordinate.

Where can I see all upcoming travels for next week at once?

The admin dashboard tile "Upcoming travels (next 7 days)" is a clickable shortcut. The same data is queryable as a filter on the bookings register report (date range = next 7 days).

11.3 Documents & PDFs

The voucher PDF shows an old logo — how do I refresh it?

Upload the new logo in Settings → Agency profile, then regenerate the voucher. New PDFs use the new logo immediately; previously generated PDFs are not back-rewritten (intentional — those are historical documents).

The PDF is generating but looks broken — boxes overflow, colours off.

Almost always a wkhtmltopdf issue. Check that the binary is installed and SNAPPY_PDF_BINARY in .env points to it. As an emergency fallback, set PDF_FALLBACK=dompdf — dompdf is less pretty but is pure-PHP and always available.

Can I rearrange the layout of the voucher PDF?

Not in v1. Header logo, footer signature, accent colour, and field-visibility toggles are configurable, but the structural Blade template is fixed by design (keeps documents pixel-stable and audit-clean). Full WYSIWYG editing is parked for phase 2.

Where are PDFs stored?

storage/app/private/documents/ and storage/app/private/supplier-docs/. Both directories live outside the public web root and are served through authenticated controller routes only. Filenames are server-generated; user-supplied names are never trusted.

11.4 AI extraction & supplier documents

Is AI extraction free?

No, each call costs ~₹0.03–0.10 to the model provider (Gemini 2.0 Flash is the cheapest sensible option). Manual mode is always available at zero cost. A monthly budget cap (default ₹300) auto-disables AI mode for agents on breach.

An AI extraction returned the wrong airline name — what now?

Just edit the field on the review form before saving. Differences between the AI's value and the saved value are logged in the booking's audit trail (provenance is preserved). The supplier file is also stored unchanged, so you can always re-check the source.

The AI extraction job is stuck on "Processing".

Make sure the queue worker is running: php artisan queue:work. The job will time out and surface as "Failed" after a default of 90 seconds — the admin then sees a clear error and can switch to Manual mode without re-uploading.

Are the supplier PDFs visible to the customer?

Never. Customers only see the Maruti Travels branded voucher generated from booking data. Supplier-issued PDFs are stored against the booking for audit and are downloadable by Admin and the assigned Agent only.

Does AI extraction work on Hindi or mixed-language documents?

Gemini 2.0 Flash handles mixed English/Hindi text well for IRCTC and some domestic hotel vouchers. If you see consistent failures on a particular supplier format, raise it — phase 2 plans a template-based parser for the top 3–5 suppliers that's cheaper and faster than per-document LLM calls.

11.5 Money, taxes & reports

How does the portal decide whether to apply CGST+SGST or IGST?

If the customer's billing state matches the Agency state in settings → CGST + SGST. Otherwise → IGST. The split happens automatically per quotation line and per invoice.

Where do I see margin / profit?

On the booking detail page (per-booking) and on the Sales & profit report (across bookings). Both are Admin-only. Agents will receive HTTP 403 if they directly call the report endpoint.

Can I export reports to Excel?

Yes — every report has an Export button that returns an .xlsx file via maatwebsite/excel. CSV is also offered for the larger reports.

A customer paid 50% — how do I record it?

On the booking, set Payment status = Partial and add a payment record with the date and method. The pending-payments report will continue to flag the remaining balance until status = Paid.

11.6 Setup, errors & troubleshooting

I'm seeing "Undefined variable $bookings" or similar runtime errors in the UI.

This is a Livewire/Blade mismatch — the view is referencing a variable that the component does not expose. Check the matching component class for the exact computed-property name (e.g. $this->recentBookings) and update the view.

Clicking a button does nothing — no error, no network call.

Check the browser DevTools console. If you see "Detected multiple instances of Alpine running", an extra Alpine was imported somewhere. Remove the extra import; Livewire 3's bundled Alpine is the only one needed.

I get "Livewire page component layout view not found: [components.layouts.app]".

Livewire's full-page-component default layout path is different from this project's. Either add #[Layout('layouts.app')] on the component class, or wrap the route in a Blade view that uses <x-app-layout> and embeds <livewire:... /> — the convention used by every other admin route.

I get an SQLSTATE 42S22: Unknown column 'created_by_id'.

A model uses the TracksAuthor trait but its migration didn't add the audit columns. Create an add_tracks_author_to_X_table migration that adds created_by_id and updated_by_id as nullable foreign keys to users (with nullOnDelete) and run php artisan migrate.

The customer login redirects to the admin login.

The verified middleware on the customer area kicks unverified users back to login. In local/dev seed customers with email_verified_at = now() in the register controller (already done in v1). In production, ensure SMTP is configured so verification emails actually arrive.

My local Vite dev server isn't serving CSS/JS.

Two checks: (a) is npm run dev running in a second terminal? (b) does the page have @vite([...]) in layouts/app.blade.php? If both are true and styles still don't load, hard-refresh (Cmd+Shift+R) to clear the cached HTML pointing at a stale asset hash.

My PHP version is older than 8.2 — will the portal run?

No. Composer will refuse to install. Upgrade PHP first: brew install php@8.2 on macOS or via Chocolatey on Windows (see the project README).

I want to wipe the local database and start fresh.

php artisan migrate:fresh --seed. This drops every table, re-runs migrations, and re-seeds the demo admin/agent. Don't run it in production — there's no "are you sure" beyond the artisan flag.

11.7 Data, privacy & audit

How long do you keep audit logs?

Indefinitely in v1. Activity log rows are immutable from the application (no delete/edit endpoint). Revisit retention if database size becomes a concern — typical agencies sit well under 1 GB after a year.

Can the audit log be edited or deleted from the UI?

No. There is no UI affordance to delete or modify audit entries, and the role policy only grants the view ability to Admin.

Where are passwords stored?

As bcrypt hashes (Laravel default, BCRYPT_ROUNDS=12). Plain-text passwords are never persisted or logged.

Is the portal GDPR-ready?

Not formally certified in v1. The data model and policies are designed to support GDPR primitives (export own data, delete own data) but the user-facing flows for those rights are deferred. Reach out before importing EU-resident customer data at scale.
